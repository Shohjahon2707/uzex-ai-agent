# Критерии приёмки UZEX AI

Источник требований: задание отбора и README набора данных. Сдача — 5 ноября 2026 до 18:00 по Ташкенту;
проверка — 10 неизвестных вопросов, каждый ответ не более 90 секунд. Интерфейс сам по себе не заменяет точность.

| Требование | Конкретный критерий | Как проверять |
|---|---|---|
| Точные ответы — 60 баллов | Числа, названия, коды и даты берутся из реестра. Есть проверяемый результат SQL. | `verify_data.py` сравнивает расчёты с CSV; `golden.py` проверяет ответы работающего агента. |
| Не выдумывать отсутствующие данные | Нет данных за 2021/2027 годы; несуществующая компания не заменяется похожей. Ошибка SQL/API обозначается ошибкой, а не отсутствием данных. | Негативные RU/UZ-вопросы в golden.csv и проверки агента. Успешный вызов инструмента — необходимое, но не достаточное условие правильности ответа. |
| RU + UZ | Вопросы на обоих языках; ответ на языке вопроса. Понятные числа, валюты, единицы. | Парные RU/UZ-вопросы и ручной просмотр ответов. Переключатель меняет язык интерфейса. |
| Обоснование — часть 20 баллов качества | Под ответом доступны строки результата и точный SQL; обрезка помечена. | Раздел «Данные и расчёт», SQL раскрывается отдельно. ИНН и коды не форматируются как суммы. |
| Валюты | USD пересчитывается по курсу даты каждой сделки; исходные валюты не складываются. | Независимый Decimal-расчёт по CSV против `sum_uzs` в SQLite. |
| Объёмы и цены | Объём = количество × лот. Единицы разделены. Средняя цена сопоставимого товара взвешена по объёму. | Проверка CSV/SQL и вопросы про объём/цену. |
| Брокеры | Если сторона не задана, обе стороны; одна сделка одного брокера учитывается один раз. Метод указан в ответе. | UNION пар (номер сделки, код брокера), сравнение с независимым проходом CSV. |
| Скорость ≤ 90 секунд | Бюджет агента 70 секунд; веб-запрос ждёт не более 80 секунд и возвращает 504, если расчёт не завершён. API/SQL получают остаток бюджета; нет автоматических повторов SDK. | Тест таймаута веб-запроса, таймер интерфейса, время в golden.py. Сетевое время и очередь production-сервера нужно измерить на VPS отдельно. |
| Работа без установки и регистрации | Публичный URL сразу открывает чат; вход не требуется. | Проверить с телефона/инкогнито после деплоя. Локальный runserver не является сдачей. |
| Постоянная доступность | Сервис переживает выход из SSH и перезагрузку; данные на месте. | systemd + production WSGI; проверить URL и `/api/health` после перезапуска. |
| Описание решения — 20 баллов | Объяснены Django + SQLite + LLM/tools, импорт, формулы, тестирование, ограничения. | README и фактические результаты проверок. Не писать, что все вопросы пройдены, пока это не проверено. |
| Правила команды | До 3 человек; код и прототип не передаются другим командам. | Приватный репозиторий; пользователь сам подаёт состав команды и контакт в форму. |

## Последовательность проверки

```bash
python manage.py test agent.tests
python scripts/verify_data.py --data data --db data/birja.db
python manage.py check_llm
python manage.py runserver
# В другом терминале:
python scripts/golden.py scripts/golden.csv http://127.0.0.1:8000
```

`verify_data.py` не вызывает LLM и не расходует API-квоту. Golden-проверка расходует квоту.
Автотесты с локальным тестовым API не подтверждают доступ к реальному Groq и не заменяют живой прогон.
Деплой и проверка публичного URL необходимы отдельно; в текущем окружении нет доступа к VPS пользователя.

В одном процессе одновременно выполняются не более двух расчётов. При занятости возвращается 503,
а очередь заданий не растёт. Истечение ожидания HTTP не убивает фоновый поток: сетевые/SQL-таймауты
агента должны завершить его; до завершения он занимает один слот. Ошибки и таймауты не выдаются за отсутствие данных.
